SOLAR / Personalized sleep prediction

Sleep prediction should remember the person.

A stepwise framework for lifelog data that separates stable personal routines from what changed on the target day. Long-term history sets the anchor; daily sensor evidence decides the correction.

Abstract

Daily sleep data is personal before it is statistical.

The same heart rate, activity level, screen time, or missing sensor record can mean different things for different users. SOLAR treats sleep prediction as a personalized baseline problem first.

What SOLAR changes

Existing lifelog-based sleep predictors usually compress sensor streams into daily observations or short-term summaries. That makes the target day easy to model, but it hides the user-specific rhythm behind the numbers.

SOLAR builds long-term personalized features from accumulated behavioral history, then uses those features to create a target-specific anchor prediction. The anchor is refined only after the model sees how the target day deviates from the participant's own long-term state.

This gives the pipeline a clear interpretation: first estimate what is typical for this person, then ask whether today's wearable and smartphone evidence should move the prediction up or down.

Motivation

Short windows miss the baseline that sleep depends on.

The motivating analysis compares short and long heart-rate windows. Across multiple sleep targets, the 28-day rolling mean shows stronger absolute correlation than the 3-day rolling mean.

01

Recent dynamics

1-7 day windows describe what changed recently: activity, physiological state, phone usage, and context.

02

Personal state

14-28 day windows and cumulative statistics describe the habitual level the target day should be compared against.

03

Deviation signal

Short-long contrasts let the model read a day as typical, unusually stressful, unusually inactive, or poorly observed.

SOLAR System

Anchor first. Refine the residual. Calibrate by target.

SOLAR does not ask one learner to understand every signal at once. It divides prediction into the same pieces the data suggests: personal baseline, day-specific variation, and target-specific temporal history.

F

Personalized features

Construct short-term, long-term, same-weekday, missingness, and deviation features from each participant's history.

1

Temporal anchor

Combine target-wise prediction sources through stacking to estimate a stable baseline probability.

2

Residual refinement

Learn the correction left unexplained by the anchor, using target-day sensor states and deviations.

3

History-aware output

Apply temporal-neighbor priors only for targets where validation shows that continuity helps.

Ablation

Ablations show the framework is doing real work.

Takeaways

The modeling order is the contribution.

SOLAR is not just another tabular ensemble. Its contribution is the sequence: construct personalized long-term context, anchor the target-wise probability, refine the residual from day-specific evidence, and preserve history-aware calibration only when it helps. 

features = short_term + long_term + short_long_contrast + participant_history
anchor   = stack_targetwise(history_priors, calendar_priors, long_term_sensor_sources)
residual = learn_target_day_correction(anchor, personalized_day_state)
output   = history_aware_refine(anchor + residual, temporal_neighbors)
